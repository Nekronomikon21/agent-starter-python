# User Stories

**Stage 3 — Operationalize success as UX.** (Pair with `failure_modes.md` and `scenarios.md`.)

> Draft v3, 2026-09-04.

## Stories

1. As a **kid**, I want to know whether my answer is right, so I stop guessing whether I'm done.
2. As a **kid who's right**, I want one line saying so, not an explanation I didn't ask for.
3. As a **kid who's wrong**, I want the **first** wrong line — not every line after it.
4. As a **kid**, I want the mistake put as a **reusable rule** ("the −4 gets multiplied too"), so I
   don't repeat it on the next question.
5. As a **kid**, I want the **correct answer straight away**, before the explanation, so I can retry
   it myself.
6. As a **kid**, I want that first message to say what the bot *got*, not that I'm *wrong* — so a
   mistaken flag isn't an accusation.
7. As a **kid**, I want `2/4` counted right when the book says `1/2`, and my own method accepted
   when it works.
8. As a **kid**, I want to be asked about my answer **only** when it genuinely couldn't be read.
9. As a **kid whose answer is a set or a sketch**, I want it looked at again rather than typed out.
10. As a **kid the bot misread anyway**, I want **"you misread my answer"** on every reply, so I have
    the last word on what I wrote.
11. As a **kid still stuck**, I want the full solution on request.

## What "good" feels like

Two seconds: *"✓ x = 17."* Move on. On the bad day: *"For 2 I get 17"*, then *"line 2 — the −4 gets
multiplied too; the rest follows fine."* What a good teacher would say in five seconds, and no more.

## Out of scope (for now)

Voice, PDFs, multi-page. Grading a whole page at once. Progress tracking. Proofs and university
maths. LaTeX rendered as images. Solving from scratch as the primary mode — story 11 only, on request.
